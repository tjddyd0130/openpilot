# ID.4 공조(Klima) 제어 조사

목표: openpilot에서 공조를 제어한다. 최종적으로는 주차 중 원격으로 켜는 것.

## 1. 전제 조건 (국내 사양)

- **통신유닛(OCU)이 물리적으로 없다.** 따라서 We Connect 앱 원격 공조는 영구히 불가능하다.
  백엔드/코딩으로 뚫는 경로는 존재하지 않는다. 이 방향은 검토 종료.
- **예약공조는 동작한다.** 이게 결정적이다. 차량이 이미 주차 상태에서 스스로 깨어나
  HV 컨택터를 닫고 히트펌프/PTC를 돌릴 능력을 갖고 있다는 뜻이다.
  우리가 HV 핸드셰이크나 웨이크업 시퀀스를 흉내낼 필요가 없고, **방아쇠만 찾으면 된다.**
- **컴마 기기는 상시전원 + `MaxTimeOffroadMin` 연장으로 주차 중에도 깨어 있을 수 있다.**
  단 `power_monitoring.py`의 저전압 셧다운(`low_voltage_shutdown`)과 배터리 용량 소진
  조건은 이 설정과 무관하게 계속 동작한다. 즉 12V가 떨어지면 어차피 꺼진다.

## 2. 공조 메시지 위치 (로그 60초 실측)

| 메시지 | 주소 | 버스 | 주기 |
|---|---|---|---|
| `Klima_11` | 0x3B5 | **bus1** | 10Hz |
| `Klima_12` | 0x668 | bus0 | 5Hz |
| `Klima_Sensor_02` | 0x5E1 | bus1 | 5Hz |
| `Klima_Sensor_04` | 0x5E9 | bus1 | 5Hz |
| `HVK_01` (HV 코디네이터) | 0x503 | **bus1** | 10Hz |
| `Klemmen_Steuerung_01` (터미널 제어) | 0x58C | **bus1** | 1Hz |
| `Klemmen_Status_01` | 0x3C0 | bus0 / bus1 | 10Hz |

`Klima_12`에 실제로 쓸 만한 신호가 있다.

```
KL_SIH_Soll_li / KL_SIH_Soll_re   시트히터 좌/우 목표단계 (0~7)
KL_LRH_Taster / KL_LRH_Stufe      열선 핸들 버튼 / 단계
FSH_Taster / HSH_Taster           앞유리 / 뒷유리 열선 버튼
KL_Geblspng_Soll                  송풍 전압 목표값
```

## 3. 걸림돌

**송신자가 Gateway다.** `Klima_11`/`Klima_12` 둘 다 DBC상 송신자가 `Gateway`다. 즉 게이트웨이가
뿌리는 상태 방송이지 공조 ECU로 가는 명령이 아니다. 같은 ID로 끼어들면 진짜 게이트웨이와
경쟁하게 되어 값이 깜빡이고 버스 에러/DTC로 이어질 수 있다. 제어가 되려면 HMI가 공조 ECU로
보내는 **요청 메시지**를 찾아야 하는데 그게 우리 DBC에 없다.

**bus1 송신 전례가 없다.** 공조 핵심 메시지들이 bus1에 있는데, MEB 안전 화이트리스트에
bus1 항목이 0개다.

```
$ grep -E "\{MSG_[A-Z0-9_]+, *1, *[0-9]+\}" safety_volkswagen_meb.h
없음
```

전부 `{MSG, 0, n}` 아니면 `{MSG, 2, n}`이다. 추가하려면 안전 C 코드를 수정해야 하고,
이는 판다 안전 경계를 넓히는 설계 결정이다.

**주차 중 버스 슬립.** 방아쇠를 찾아도 차가 자고 있으면 받을 ECU가 없다. 깨우는 방법이
별도로 필요하다. 다만 예약공조가 발동할 때 차가 어떻게 깨는지 관찰하면 단서가 나올 수 있다.

## 4. 1단계 실험: 예약공조 발동 순간 스니핑

`selfdrive/debug/car/vw_meb_parked_can_sniff.py`

읽기 전용이다. CAN 송신도 파라미터 쓰기도 없다. `pandad`가 `always_run` 프로세스라
시동이 꺼져 있어도 `can` 소켓으로 프레임이 계속 올라오므로, openpilot을 죽이거나 판다를
직접 열 필요가 없다.

기본 동작은 변화분만 기록한다. 버스가 자는 동안은 거의 안 쌓이고 차가 깨는 순간
폭발적으로 기록되며, `SLEEP_GAP_S`(3초) 이상 침묵 뒤 프레임이 재개되면 `{"type":"wake"}`
레코드로 경계를 표시한다. 이 경계가 분석의 앵커다.

절차:

1. 인포테인먼트에서 예약공조 시각을 10~15분 뒤로 설정
2. SSH로 백그라운드 실행
   ```
   cd /data/openpilot && nohup python selfdrive/debug/car/vw_meb_parked_can_sniff.py \
     --out /data/media/0/parked_can.jsonl > /data/media/0/sniff.log 2>&1 &
   ```
3. 시동 끄고 내려서 문 잠그기
4. 예약 시각 지나 공조가 도는 것을 확인한 뒤 `pkill -f vw_meb_parked_can_sniff`
5. `/data/media/0/parked_can.jsonl` 회수

이 한 번으로 방아쇠 메시지, 웨이크업 방식, 그리고 기기가 실제로 얼마나 버티는지까지
같이 나온다.

## 5. 이후 단계 (1단계 결과에 따라)

- 방아쇠가 우리가 읽는 버스에 있으면: 해당 메시지의 송신자와 구조 분석
- 송신 필요 버스가 bus1이면: 판다 안전 화이트리스트 확장 검토 (설계 결정 필요)
- 웨이크업 방식 파악 후 openpilot이 동일하게 유발 가능한지 판단
- 폰에서 기기로 명령을 넣는 경로는 마지막 문제 (SSH / comma connect / 로컬 엔드포인트)

## 6. 참고: 앱 없이 되는 순정 로컬 기능

- 출발시간 예약: 설정 시각과 목표 온도를 보고 최대 30분 전부터 자동 예열. 백엔드 불필요.
- 보조 공조(Standklimatisierung): 키 인식 거리에서 잠금해제 시 공조 시작.

국내 사양에 예약공조가 있는 것은 확인됨.
